# resolve-lang v0.4.0 — HIR 0.4

**On hir-lang 0.4.** v0.4.0 moves resolve-lang to hir-lang 0.4 (HIR spec v3).
typeck-lang 0.3 was already on hir-lang 0.4 while lower-lang, resolve-lang, and
bcgen-lang were on 0.3, so LexerSketch could not put them in one build: rustc
sees two `hir_lang` crates and rejects the `Hir` passed between them (E0308).
This release removes resolve-lang from that split and resolves every form 0.4
added: place-once aliases (`let_place`), keyed `yield` and `yield from`, and
union and intersection types.

## What is resolve-lang?

The semantic-analysis-tier crate of the `-lang` family that owns name
resolution. Every language LexerSketch forges lowers to HIR, so one resolver
serves all of them: the differences between PHP, Python, and Kraken scoping are
a `Policy`, not separate code. It depends on `hir-lang` (the representation it
resolves) and `intern-lang` (to spell and fold names), and nothing else.

## What's new in 0.4.0

### `let_place`: one alias, one body, no frames

```rust
use hir_lang::{BinderKind, Builder, Expr, Name, Res};
use intern_lang::Interner;

// fn f(a, k) { let_place p = a[k] in p = p }
let mut names = Interner::new();
let (a, k, p) = (
    Name::new(names.intern("a")),
    Name::new(names.intern("k")),
    Name::new(names.intern("p")),
);
let mut b = Builder::new();
let (pa, a_binder) = b.local_param(a);
let (pk, _) = b.local_param(k);
let base = b.name_expr(a);
let index = b.name_expr(k);
let place = b.expr(Expr::Index { base, index });
let alias = b.new_binder(p, BinderKind::Place);
let target = b.name_expr(p);
let value = b.name_expr(p);
let body = b.expr(Expr::Assign { target, op: None, value });
let lp = b.expr(Expr::LetPlace { binder: alias, place, body });
let fbody = b.block(&[], Some(lp));
let f = b.func(Name::new(names.intern("f")), &[pa, pk], fbody);
let root = b.module(None, &[f]);
let hir = b.finish(root)?;
let unit = hir.unit();

let res = resolve_lang::resolve(hir, &names)?;
assert!(res.is_clean());
let hir = res.hir(unit).unwrap();
let res_of = |e| match *hir.expr(e) { Expr::Path(p) => hir.path(p).res, _ => unreachable!() };
assert_eq!(res_of(base), Res::Local(a_binder));
assert_eq!(res_of(target), Res::Local(alias));
# Ok::<(), Box<dyn std::error::Error>>(())
```

Lowering writes `let_place` for a compound assignment whose operator is not an
OPS op (PHP `.=`, `??=`, `$a[f()]++`), so the place's operands are evaluated
once. resolve-lang follows the spec's scoping rule exactly:

- The place's operands resolve in the enclosing scope, where the alias is not
  yet visible: `let_place p = p[0] in p` reads an outer `p` in the place and
  the alias in the body.
- The alias is visible in the body only; past it, the name means what it meant
  before.
- It crosses no frame. A closure in the body that names it, even one with
  implicit captures, gets `CannotCapture`, where an ordinary local would be
  captured.
- An alias from a template carries the expansion's mark. The template's own
  `p'e1` resolves to it; the user's `p` in the template's hole does not, and is
  never offered the alias as a did-you-mean. In the index the alias is a
  `SymbolKind::Place` definition whose locations all map to the expansion's
  call site, so a rename lists them under `outside_source`.
- The `Shadowing` deny policies do not apply to it: the user never declares an
  alias, so it is not reported, and a local declared inside its body is not
  reported for reusing its name.

### Keyed yields, `yield from`, unions and intersections

`Yield { key, value }` resolves its key, then its value; `YieldFrom` its
operand. Every type path inside a `Ty::Union` or `Ty::Intersection` resolves
like any type path. hir-lang's `finish` now normalizes these types before the
resolver sees them: members sorted, nested ones flattened, a nullable member
hoisted, repeats dropped. A dropped member becomes a dead error path that no
walk reaches; resolve-lang leaves it alone (no resolution, no diagnostic, no
index entry), as it does every subtree a lenient repair cuts off.

### The HIR spec's own example

HIR spec §9.6 (Mox `function tag(string|int|null $k, array $a) { $a[$k] .= "!"; }`)
is built the way lowering builds it, with the template's names unresolved and
marked, resolved under `Policy::php()`, and printed: the output is the spec's
text, character for character (`tests/hir_0_4.rs`).

### `lookup_local_in`: evaluated, not used

hir-lang 0.4 adds `Hir::lookup_local_in(path, name, ns)` for the gap this crate
recorded in 0.2 (ISSUES P13): a type parameter named by a path in another
namespace (`T::new`). resolve-lang already finds it through the type table's
shadow stack, which also folds case in a case-insensitive type table (`t::new`
finds `T` under `Policy::php()`) and meets value paths when every namespace is
one table (`Policy::python()`, where a value `T` is the wrong kind). An
exact-name lookup in one namespace covers neither, so switching would mean two
mechanisms for one rule. Both cases are tested.

## Breaking changes

- Depends on `hir-lang` 0.4 instead of 0.3. Callers must move to hir-lang 0.4
  at the same time.
- `SymbolKind::Place` is new (the enum is `#[non_exhaustive]`).

Migration: bump `resolve-lang = "0.4"` and `hir-lang = "0.4"` together, and
follow hir-lang's 0.4 notes for the HIR you build.

## Guarantees and how they are checked

- The differential property tests now generate generic parameters,
  `let_place` aliases (with operands and bodies of any form, closures
  included), keyed `yield` and `yield from`, and union, intersection, and
  nullable type annotations, and compare every reference with a reference
  resolver that models place aliases (visible in the body, crossing no frame)
  and type parameters (crossing closures, not function items). A generator
  check requires that place aliases, type parameters, and dropped union
  repeats each actually occur.
- Every reference still ends resolved or with exactly one diagnostic, the
  result still validates, and the index stays consistent, on all of those
  programs; repeats that normalization drops are checked to be untouched.
- Everything 0.3 guaranteed still holds: resolve-lang's existing tests passed
  against hir-lang 0.4 before any test was extended.

## Performance

Library numbers, measured with Criterion on a desktop x86_64 machine (Windows,
release profile), resolution including indexing and writing the `Hir`. The
machine was shared with other builds while these ran, so 0.3.0 and 0.4.0 were
run back to back, twice, under the same load:

| Benchmark | Size | 0.3.0 (hir-lang 0.3) | 0.4.0 (hir-lang 0.4) |
|---|---|---|---|
| One unit | 124,000 nodes | 20.9 / 20.5 ms | 20.3 / 20.3 ms |
| One unit | 1,240,000 nodes | 268 / 250 ms | 257 / 251 ms |
| Eight units | 992,000 nodes | 209 / 199 ms | 188 / 188 ms |
| `Index::at` for every reference | 124,000-node unit | 9.6 / 9.1 ms | 8.9 / 9.0 ms |

No regression. New benchmark `resolve_hir_0_4_forms`: 2,000 generator
functions, each with a union-typed parameter `T | U | ?R`, four `let_place`
compound assignments calling other functions, a keyed `yield`, and a
`yield from`: 192,000 nodes in 31 ms (6.2 million nodes per second) on the
loaded machine.

## Not in this release

- Incremental update hooks (v0.5.0).
- The 0.3 leniencies and gaps stand: PHP's bare-name and callee leniencies, no
  `$` sigil on HIR paths, ASCII-only case folding, `symbol-lang` and
  `module-lang` not wired (ISSUES M37, M38), no `diag-lang` conversion.
